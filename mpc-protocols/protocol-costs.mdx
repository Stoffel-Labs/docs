## What the bounds count

`n` is computing-party count, `t` the corruption parameter, `B` the number of field values in a batch, `d` polynomial degree, and `L` broadcast payload bytes. Bounds describe local work unless labeled total communication. Field multiplication, group scalar multiplication, encoding and hashing are different costs.

A protocol stage means a causal dependency, not a fixed latency. One reliable broadcast itself has several message stages. Parallel openings need not add circuit depth, while sequential chunks and on-demand preprocessing do. No finite successful-completion bound applies to a generator waiting on a silent required dealer.

Let `I(n,d,t)` be one robust polynomial reconstruction attempt, including fallback decoding. Let `R(L)` be one reliable broadcast, including local encoding/hash work. These names prevent decoder and network work from disappearing inside an advertised local-arithmetic bound.

## HoneyBadgerMPC preprocessing

| Component | Dependency stages | Local computation, excluding broadcast overhead | Paper |
| --- | --- | --- | --- |
| Raw double sharing | All-party dealing, requiring every dealer | Two degree families; FFT evaluation costs `O(BN log N)` with actual domain size `N`; all-party delivery has `O(n²B)` total scalar volume | [1][9] |
| RanSha | Deal, mix, verifier reconstruction, verdict RBC | `O(Bn²)` matrix field work; verifiers add reconstruction; `2t` verdict broadcasts | [1] |
| RanDouSha | Double sharing, mix/check both degrees, verdict RBC | Two matrix transforms plus checking reconstruction at degrees `t` and `2t`; broadcast overhead separate | [1] |
| Triple generation | Degree-`2t` BatchRecon after random shares/double shares exist | `O(B)` local products/corrections plus reconstruction; upstream generation adds cost when pools are empty | [1][12] |
| Random bits / PRandBitD | Multiplication, opening and generation/checking stages as selected | Field square roots/inversions or cross-field checks plus bit-generation/decode work; depends on requested width | [8] |
| PRandInt | Local weighted assembly after bits are available | Linear in supplied bit count; bit generation is additional | [8] |

These preprocessing paths are not uniformly asynchronous-live against faulty withholding. Fixed-point adaptations additionally need their own active-security and statistical-mask analysis; the cited fixed-point source is semi-honest.[8]

## HoneyBadgerMPC online

| Operation | Dependency stages | Local computation | Paper |
| --- | --- | --- | --- |
| Add/subtract/public scaling | Zero communication | `O(B)` field operations | [9] |
| Secret multiplication | Both masked differences opened in parallel; full packs use BatchRecon, remainder uses RBC | `O(B)` field arithmetic plus both reconstruction paths | [1][12] |
| Input | Private mask opening to client, then masked-correction RBC | Client robust reconstruction; party subtraction | [1] |
| Output to client | One direct party-to-client delivery layer | Robust reconstruction for each output, possibly retried on arrivals | [1][9] |
| Probabilistic truncation | One RBC-based masked opening, then local adjustment | Linear mask assembly plus decoding and integer/field work | [8] |
| Fixed-point multiplication | Multiplication followed by truncation | Sum of those two operations | [8][12] |
| Division by a public constant | Public reciprocal/scaling, then truncation | Public reciprocal and local scaling plus truncation | [8] |

BatchRecon packs `d+1` values and uses two causal exchange stages. Per pack, account for `O(n(d+1))` transform work and decoding in both stages. Multiple packs share a wire session, giving `O(n²)` message count per aggregated session while bytes still grow with data volume. Robust interpolation can make up to `t` Gao fallback attempts on successively larger subsets.[1][6][7]

Do not substitute the `O(n log n)` transform bound from a paper for the concrete dense-polynomial decoder. Cached setup, retries, arrival order and selected field change the implementation cost.[5][17]

## AVSS preprocessing and online

| Phase/component | Dependency stages | Local computation, excluding RBC | Paper |
| --- | --- | --- | --- |
| Preprocessing: encrypted dealing | One RBC layer per dealer batch | Dealer `O(Bnt)` field evaluation, `O(B(t+1))` group commitments, `O(n)` DH operations and `O(Bn)` encryptions; recipient `O(B(t+1))` group verification per dealer | [9][10], adapted wrapper |
| Preprocessing: random shares | `n` concurrent dealings, wait for all, then mixing | `O(Bn²)` field and `O(Bn²(t+1))` group work, plus all dealings | [1][10], adapted mixing |
| Preprocessing: triples | `2t+1` fixed dealers reshare products; wait for all | For `m=2t+1`, combining costs `O(Bm(t+1))` group work; recomputed weights add `O(Bm²)` field work and `O(Bm)` inversions | [12][15], algebraic ancestry only |
| Online: add/subtract/public scaling | Zero communication | `O(t)` commitment operations per scalar; scaling uses group scalar multiplication | [10] |
| Online: multiplication | Both masked differences share one all-party RBC layer | `O(Bt)` local commitment work; a readiness attempt verifies `O(Bqt)` group work for `q` responders; repeated arrivals can total `O(Bn²t)` verification | [12] |
| Online: input | Mask shares to client, then masked-correction RBC | Group verification, same-commitment grouping and interpolation | [1][10] |
| Online: output | Direct shares to client | Group verification, grouping and interpolation | [9][10] |

AVSS reconstruction currently builds full interpolation polynomials. Straightforward dense arithmetic is `O(q³)` for `q` points, rather than a constant-term-only `O(q²)` algorithm. Grouping and verification may repeat as messages arrive. The orchestrator serializes chunks of up to 128 and may replenish preprocessing inside an online call.

The current AVSS triple generator does not check the product relation under malicious dealers. These costs describe the implemented work, not an actively secure replacement. AVSS does not supply this revision's HoneyBadger fixed-point subprotocols.

## Shared distributed primitives

| Component | Stages and communication | Local computation | Paper association |
| --- | --- | --- | --- |
| Bracha RBC | INIT/ECHO/READY; `O(n²)` messages and `O(n²L)` total payload bytes | Up to `O(nL)` local payload/hash processing under unique bounded traffic | [13] |
| AVID-style RBC | Shard/ECHO/READY; `O(n²)` messages; `O(n²L/k+n² log(n) h)` total bytes for `k` data shards and hash width `h` | Reed–Solomon encode/decode/verification plus Merkle proofs; not free network latency | [3] |
| ABA/common coin | Repeated EST/AUX/coin; nominal `O(n²)` control messages per iteration | Signature-share checks, threshold combination and state processing | [4][16] |
| ACS | `n` RBCs plus `n` ABAs and selected-value completion | Sum of constituent costs plus set handling | [4] and its BKR reference |
| Trusted coin-key dealer | Dealer-to-party setup, `O(n)` messages | Key polynomial generation/evaluation and distribution | [4] and its threshold-signature reference |

ABA/ACS are standalone components in this revision, not integrated into the default MPC preprocessing generators. Their implemented state and coin lifecycle do not establish the papers' expected termination bounds. The coin dealer is trusted centralized setup, not DKG.

Shamir and Feldman local helpers have no network rounds. Pedersen commitment support costs linear group work in polynomial degree, but the `common/acss` module is not a complete hbACSS implementation. Its preprocessing/online network guarantees are not applicable.[2][9][10][11]

## Planning capacity

Measure both a prefilled-pool run and a run that generates its material. Record field/curve, `n,t`, input widths, multiplication depth, batch sizes, RBC variant, network conditions and retry/failure counts. Protocol dependency stages help compare circuit shapes; they do not replace end-to-end measurements or security review.
